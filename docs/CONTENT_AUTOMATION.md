# 콘텐츠 자동화 운영 설계

## 기본 원칙

자동화는 출처가 있는 사실을 정리하고 초안을 생성하는 데 사용합니다. AI 생성 문장만으로 사실을 검증한 것으로 취급하지 않습니다. `needs_review` 상태의 문서는 자동 게시되지 않습니다.

## 권장 파이프라인

1. **수집**: 승인된 공식 API/피드 또는 운영자가 제공한 출처 URL만 사용합니다.
2. **정규화**: 원본 데이터, 원본 URL, 수집 시각, 필드별 확인 상태를 저장합니다.
3. **검증**: 런타임 스키마로 형식을 검사하고, 필수 사실·이미지 권리·제휴 링크 상태를 확인합니다.
4. **초안 생성**: 지역·여행 목적에 맞는 편집 구조를 채우되, 입력되지 않은 사실을 만들어내지 않습니다.
5. **중복/품질 점검**: 다른 글과 유사한 문구, 얇은 콘텐츠, 과도한 키워드 반복을 검토합니다.
6. **사람의 승인**: 모든 사실 주장, 이미지 권리, 링크, 고지를 사람이 확인합니다.
7. **정적 빌드**: 승인된 콘텐츠만 페이지 생성 입력에 반영합니다.
8. **게시 후 확인**: 링크, 메타데이터, 구조화 데이터, 색인, 광고 위치를 검사합니다.

## 필드 권장안

- `sourceUrl`, `sourceLabel`, `checkedAt`
- `factStatus`: `verified | unverified | stale | disputed`
- `imageRights`: `owned | licensed | approved_feed | needs_review | unknown`
- `affiliateStatus`: `approved | unapproved | missing | needs_review`
- `editorialStatus`: `draft | needs_review | approved | published | archived`
- `lastReviewedAt`, `reviewer`

## 게시 차단 조건

- 출처가 없는 중요 사실
- 확인 날짜가 없는 변동 정보
- 사용 권한을 확인하지 못한 이미지
- 실제 계정 승인 상태를 확인하지 못한 제휴 링크
- 가격/재고/평점을 실시간으로 검증하지 못한 경우
- 개인정보/광고 고지가 실제 구현과 다른 경우
- 자동 생성 콘텐츠가 독자에게 고유한 가치를 제공하지 못하는 경우

## API 통합

Agoda API의 URL, 필드, 인증, 제한, 이미지 이용 규칙은 실제 계정 문서에서 확인하기 전까지 구현하지 않습니다. 비밀키는 서버 환경 변수로만 보관합니다. API 응답은 `unknown`으로 취급한 후 런타임 검증을 거칩니다. 오류 응답이나 빈 결과를 정상 데이터로 위장하지 않습니다.
