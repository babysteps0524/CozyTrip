# 콘텐츠 초안·검수·발행 워크플로

이 문서는 CozyTrip 콘텐츠의 초안 생성, 검수, 게시 승인, 발행 전체 흐름을 정의합니다. AGENT.md §5.4(콘텐츠 상태)와 §7(AI-assisted blog-drafting automation)을 따릅니다.

## 1. 콘텐츠 상태 모델 (5단계)

호텔, 명소, 지역, 가이드 콘텐츠는 다음 5단계 상태 전이를 따릅니다.

| 상태        | 의미             | 사이트 노출 | sitemap 포함 |
| ----------- | ---------------- | ----------- | ------------ |
| `draft`     | 초안 작성 중     | 비공개      | 제외         |
| `review`    | 편집 검토 중     | 비공개      | 제외         |
| `approved`  | 편집자 승인 완료 | 비공개      | 제외         |
| `published` | 게시됨           | 공개        | 포함         |
| `archived`  | 보관됨           | 비공개      | 제외         |

상태 전이 순서: `draft → review → approved → published → archived`

- 새 콘텐츠는 기본적으로 `draft` 상태로 생성됩니다.
- `approved` 이전 상태의 콘텐츠는 공개 페이지와 sitemap에 포함되지 않습니다.
- `published`로 전환하기 전에는 사실 검증, 출처 확인, 이미지 권리, 제휴 링크 검증이 모두 완료되어야 합니다.
- `archived`는 언제든지 가능하며, 복구 시에는 재검토가 필요합니다.

## 2. 전체 파이프라인

```
정보 수집 → 출처 기록 → 초안 생성 → 자동 검증 → 인간 검토 → 승인(approved) → 게시(published)
```

### 단계 A: 대상 선정

1. 호텔, 명소, 지역, 가이드 중 콘텐츠 유형을 선택합니다.
2. 중복 slug, 유사 주제 여부를 확인합니다.
3. 해당 페이지를 만들 독자 가치가 있는지 판단합니다.
4. 출처를 확보할 수 없는 대상은 자동화 대상에서 보류합니다.

### 단계 B: 데이터 입력/수집

허용된 데이터 경로만 사용합니다:

- 운영자가 직접 입력한 데이터
- 호텔·명소 공식 웹사이트(이용 약관 준수)
- 공식 관광/교통 기관의 재사용 가능한 정보
- 계정 권한과 문서상 허용 범위가 확인된 아고다 API/피드/제휴 도구
- 명시적으로 재사용 허가를 받은 제3자 데이터

금지:

- 접근 권한 없는 비공개 API 사용
- 로그인/접근 제한 우회, CAPTCHA 우회, 속도 제한 우회
- 웹사이트 약관을 위반하는 대량 스크래핑
- 이미지/리뷰/가격 데이터 무단 복제
- API를 사용하지 않았는데 사용했다고 기록

### 단계 C: 초안 생성

브라우저 `/studio/` 또는 CLI `bun run content:draft`를 사용합니다.

1. 입력 필드 유효성 검사 (호텔명, 도시, 요약 40자 이상, URL 형식 등)
2. 제목·요약·본문·출처·검수 메모 생성
3. Markdown 파일로 내보내기 또는 다운로드
4. `draft` 상태로 생성 (자동 게시 없음)
5. 초안 생성만으로 외부 API 호출, 예약, 구매를 수행하지 않음

### 단계 D: 자동 검증

`bun run content:validate`로 다음을 확인합니다:

- 필수 식별자와 slug 중복 여부
- 참조된 지역 slug 존재 여부
- URL 스킴이 `https:` 또는 안전한 경로인지
- 잘못된/빈 제목
- 출처 없는 구체적인 사실
- 확인되지 않은 이미지 권리
- 깨진 제휴 링크 또는 비정상 링크 형식
- 필수 제휴 고지 누락
- 게시 승인 없이 공개 대상에 포함된 글

### 단계 E: 인간의 검토

편집자가 다음을 확인합니다:

- 공식 호텔/명소 정보와 문장 사이의 관계
- 이미지 권리 (출처, 라이선스, 크레딧)
- 위치·교통 설명의 정확성
- 편집적 판단의 타당성과 중복성
- 제휴 링크의 도착 페이지 및 추적 규칙
- 광고 배치의 적절성
- 오탈자와 한국어 자연스러움
- 날짜에 민감한 내용의 확인 날짜

승인 시 `approved` 상태로 변경하고 검토 일자를 기록합니다.

### 단계 F: 게시

`approved` 상태인 콘텐츠만 `published`로 전환되어 정적 빌드에 포함됩니다. 게시 전 링크와 이미지 권리를 재검증하고, 사itemap과 내부 링크를 갱신합니다.

## 3. 게시 차단 조건

다음 조건 중 하나라도 충족하면 공개할 수 없습니다:

- 출처가 없는 중요 사실
- 확인 날짜가 없는 변동 정보 (운영 시간, 요금, 거리 등)
- 사용 권한을 확인하지 못한 이미지
- 실제 계정 승인 상태를 확인하지 못한 제휴 링크
- 가격/재고/평점을 실시간으로 검증하지 못한 경우
- 개인정보/광고 고지가 실제 구현과 다른 경우
- 자동 생성 콘텐츠가 독자에게 고유한 가치를 제공하지 못하는 경우

## 4. 도구

| 도구               | 경로                       | 용도                                             |
| ------------------ | -------------------------- | ------------------------------------------------ |
| 브라우저 초안 도구 | `/studio/`                 | Markdown 초안 생성 및 다운로드 (비공개, noindex) |
| CLI 초안 생성      | `bun run content:draft`    | 입력 JSON 기반 Markdown 초안 생성                |
| CLI 상태 전이      | `bun run content:status`   | 호텔 파일 frontmatter 상태 변경                  |
| 콘텐츠 검증        | `bun run content:validate` | 호텔/명소 데이터 JSON/MD 검증                    |

> 브라우저 `/studio/`에서 생성된 입력 내용은 서버로 전송되지 않으며, 초안은 자동 게시되지 않습니다. 데이터 persistence는 이루어지지 않으므로, 생성 후 Markdown 파일을 다운로드하여 보관해야 합니다.
